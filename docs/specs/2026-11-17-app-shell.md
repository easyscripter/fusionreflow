# Каркас приложения: спека

**Задача плана:** «Каркас приложения» — новая задача перед 3.2 (решение человека 2026-11-17: сначала каркас с
экранами-заглушками, потом экраны)
**Стек:** Flutter (+ ресурсы Android)
**Ветка:** `feat/app-shell`
**Статус:** утверждена человеком 2026-11-17

## Цель

Приложение запускается как настоящее: системный сплеш на тёмном фоне с логотипом висит, пока приложение не готово,
дальше открываются три раздела из дизайна (Библиотека, Закладки, Настройки): на телефоне через нижнюю панель, на
планшете через боковую рейку. В лаунчере стоит адаптивная иконка по дизайн-системе. Разделы пока заглушки, экраны
3.2 и дальше встают в готовые маршруты.

## Источник

Артефакт Claude Design из `docs/design.md`, доски «Библиотека», «Библиотека · малый телефон», «Библиотека · планшет»,
«Библиотека · планшет, альбомная», «Настройки приложения», «Экран запуска», «Иконки» (раздел «Иконка приложения»),
«UI-kit для Flutter» (`NavigationBar`, `NavigationRail`). Всё нужное из них записано ниже, артефакт открывать не нужно,
кроме экспорта PNG логотипа (см. «Входные материалы»).

## Границы

В задаче:
- зависимость `go_router`, роутер с тремя ветками и оболочкой (`StatefulShellRoute.indexedStack`);
- оболочка: `NavigationBar` на `compact`, `NavigationRail` на `medium` и `expanded` (`WindowSizeClass` из темы);
- три экрана-заглушки: Библиотека, Закладки, Настройки;
- запуск: нативный сплеш (Android 8–11 и 12+), снятие сплеша только после инициализации, экран ошибки запуска;
- иконка приложения: адаптивная + монохромная (Android 13), генерация `flutter_launcher_icons`;
- строки в ARB (ru, en), тесты, правка `docs/design.md`;
- удаление `HomeScreen`; кнопка спайка переноса (debug) переезжает на заглушку Библиотеки.

Не в задаче (и где это делается):
- экран чтения и его маршрут — блок 5 (5.3), вместе с читалкой (решение человека);
- содержимое Библиотеки, кнопка «Добавить» — 3.2 и 4.3;
- содержимое Закладок и Настроек приложения — вне плана 2 (в каркасе только заглушки);
- онбординг — вне плана 2;
- экран-сплеш во Flutter (надпись, подзаголовок, версия из макета «Экран запуска») — не делается: сплеш только
  нативный, без искусственной выдержки (решение человека);
- свой набор линейных иконок (34 SVG) — отдельная задача; в каркасе стандартные `Icons` (см. решения);
- поиск, меню «Ещё», FAB — 3.2 / 4.3;
- iOS — не поддерживается.

## Входные материалы (до старта разработчика)

Человек (или аналитик по его просьбе) экспортирует из Claude Design два PNG и кладёт их в ветку:

| Файл | Что | Требования |
|---|---|---|
| `assets/branding/logo_mark.png` | знак (книга с волнами) из логотипа | 1024×1024, прозрачный фон, без градиентной подложки, знак по центру, поля ≥ 10% |
| `assets/branding/logo_monochrome.png` | силуэт книги для монохромной иконки Android 13 | 1024×1024, белый (`#FFFFFF`) силуэт без градиента на прозрачном фоне, те же размеры и положение, что у знака |

Исходник — JPEG 2000×2000 из артефакта (`/_blob/12707d47de9e152f7cc93431bacf7fda`), у него фон вшит, поэтому он не
годится для переднего слоя адаптивной иконки. **Сделано 2026-11-17:** аналитик вырезал знак из этого JPEG (подложка
снята, края сглажены, знак занимает 80% холста), силуэт — альфа знака белым; оба файла в ветке. Знак рассчитан на
тёмный фон `#0C0F22` (на белом в просвете второй волны виден небольшой зубец — на тёмном фоне и в размере иконки
незаметен). При `adaptive_icon_foreground_inset: 16` знак почти касается круга маски — для полей около 20% нужен
inset порядка 26–28; итог разработчик подбирает и пишет в PR.

## Новые зависимости (согласованы с человеком 2026-11-17)

- `dependencies`: `go_router: ^18.1.4` (BSD-3-Clause, пакет команды Flutter).
  Почему подходит: `StatefulShellRoute.indexedStack` даёт оболочку с нижней панелью / рейкой и сохраняет состояние
  каждой вкладки (свой стек и прокрутка); полноэкранный маршрут поверх оболочки (читалка в 5.3) — обычный `GoRoute` с
  `parentNavigatorKey` корня; кнопку «назад» Android обрабатывает сам (`MaterialApp.router`); роутер — провайдер
  Riverpod, в виджет-тестах подменяется `initialLocation`; ссылки на разделы — строковые пути, без глобального состояния.
- `dev_dependencies`: `flutter_launcher_icons: ^0.14.4` (MIT; тянет `image` — MIT). Только генерация ресурсов при
  разработке, в APK не попадает. Версию указать явно: без неё pub выбирает 0.9.3. При подборе версий pub понижает
  транзитивный `cli_util` 0.6.0 → 0.4.2 — это допустимо.
- Пакет сплеша (`flutter_native_splash`) не нужен: сплеш — несколько XML-файлов вручную.
- *Решение аналитика:* строку в README («Third-party components») для `go_router` не добавляем — там перечислены только
  встроенные ресурсы (шрифты, словари), а лицензии Dart-пакетов Flutter сам включает в `LicenseRegistry`
  (`showLicensePage`), как у уже подключённых `flutter_riverpod`, `drift` и др.

## Интерфейсы

### Константы бренда (`lib/ui/core/theme/app_brand.dart`)

```dart
abstract final class AppBrand {
  /// Фон сплеша, иконки и плашки логотипа (#0C0F22).
  static const Color background = Color(0xFF0C0F22);
  static const String logoMarkAsset = 'assets/branding/logo_mark.png';
}
```
Тот же цвет — в `android/app/src/main/res/values/colors.xml` (`<color name="brand_background">#0C0F22</color>`):
это ресурс другой платформы, общего источника нет, в обоих местах комментарий со ссылкой друг на друга.
`AppBrand.background` совпадает с `darkColorScheme.surfaceContainerLowest`, но это разное знание (бренд и тема меняются
по разным причинам) — комментарий «почему не общее».

### Маршруты (`lib/routing/`)

```dart
// app_routes.dart
abstract final class AppRoutes {
  static const library = '/library';
  static const bookmarks = '/bookmarks';
  static const settings = '/settings';
  static const hyphenSpike = '/library/hyphen-spike'; // только debug
}

// app_router.dart
@Riverpod(keepAlive: true)
GoRouter appRouter(Ref ref);   // ref.onDispose(router.dispose)
```
- `initialLocation: AppRoutes.library`.
- `StatefulShellRoute.indexedStack(builder: (context, state, shell) => AppShell(navigationShell: shell), branches: …)`,
  три ветки в порядке Библиотека (0), Закладки (1), Настройки (2), у каждой свой `GlobalKey<NavigatorState>`.
- В ветке Библиотеки дочерний маршрут `hyphen-spike` → `HyphenSpikeScreen`, только при `kDebugMode`
  (в release его нет в списке маршрутов).
- Неизвестный путь → `redirect` на `AppRoutes.library`.

### Оболочка (`lib/ui/shell/widgets/`)

- `app_shell.dart` — `AppShell({required StatefulNavigationShell navigationShell})`. Класс окна —
  `windowSizeClassOf(MediaQuery.sizeOf(context).width)`:
  - `compact` → `Scaffold(body: navigationShell, bottomNavigationBar: NavigationBar(...))`, три
    `NavigationDestination` (Библиотека, Закладки, Настройки);
  - `medium`, `expanded` → `Row(NavigationRail, VerticalDivider(width: 1), Expanded(navigationShell))`.
  - Переход: `navigationShell.goBranch(i, initialLocation: i == navigationShell.currentIndex)` (повторный тап по
    активному пункту возвращает в корень раздела).
  - Высоты, цвета, индикатор — из `navigationBarTheme` / `navigationRailTheme` темы (спека 2.1); в оболочке их не задаём.
- Рейка как в макете: сверху `leading: AppLogo()` (отступ снизу `AppSpacing.s16`), пункты Библиотека и Закладки
  (`destinations`), внизу «Настройки» — `trailing: RailSettingsButton(...)`, `trailingAtBottom: true`. На вкладке
  Настроек `selectedIndex: null`, кнопка выделена; на остальных вкладках `selectedIndex` = индекс ветки.
  `labelType: NavigationRailLabelType.all`.
- `rail_settings_button.dart` — `RailSettingsButton({required bool selected, required VoidCallback onTap})`: выглядит
  как пункт рейки (значок 24 в индикаторе `primaryContainer` при выборе, подпись `labelSmall`, цвета как у пунктов
  рейки из темы), цель касания ≥ 48×48, `Semantics(button: true, selected: selected, label: navSettings)`.
- `app_logo.dart` — `AppLogo({double size = 48})`: квадрат `size`, скругление `AppRadius.dialog` (12), фон
  `AppBrand.background`, внутри `Image.asset(AppBrand.logoMarkAsset)`, `semanticLabel` = `appTitle`.
- Значки (*решение аналитика*): `Icons.menu_book_outlined` (Библиотека), `Icons.bookmark_border` (Закладки),
  `Icons.tune` (Настройки), одинаковые для выбранного и невыбранного состояния (выбор показывает индикатор).

### Кнопка «назад» Android

- На корне вкладки Закладки или Настройки «назад» переключает на Библиотеку (`goBranch(0)`), приложение не закрывается.
- На корне Библиотеки «назад» закрывает приложение (поведение по умолчанию).
- Внутри вкладки (например, debug-спайк в Библиотеке) — обычный возврат по стеку вкладки.
- Реализация — на выбор разработчика (например, `PopScope` в `AppShell`, срабатывающий только когда стек текущей
  вкладки пуст); критерий — тесты «назад» ниже, включая возврат из спайка внутри Библиотеки.

### Запуск и сплеш

**Что значит «готово»:** мост Rust инициализирован и хранилище книг открыто (база Drift открыта, уборка сирот
из 3.1 прошла). Только после этого рисуется первый кадр Flutter, и система убирает сплеш.

- `RustCoreService.init()` (новый метод): `if (RustLib.instance.initialized) return; await RustLib.init();` —
  повторный вызов безопасен (повторная попытка после ошибки, интеграционные тесты, где `RustLib.init` уже вызван).
- `lib/config/app_startup.dart`:
  ```dart
  /// Сколько ждать инициализации, прежде чем показать ошибку вместо вечного сплеша.
  const Duration startupTimeout = Duration(seconds: 20);

  @Riverpod(keepAlive: true)
  Future<void> appStartup(Ref ref);
  ```
  Тело: `ref.read(rustCoreServiceProvider).init()`, затем `ref.read(bookRepositoryProvider).watchAll().first`
  (открывает базу и запускает уборку сирот), всё под `.timeout(startupTimeout)`. Ошибки не глотаются: они становятся
  `AsyncError` провайдера.
- `lib/main.dart`:
  ```dart
  final binding = WidgetsFlutterBinding.ensureInitialized()..deferFirstFrame();
  runApp(const ProviderScope(child: FusionReflowApp()));
  ```
  `RustLib.init()` из `main` убирается (он теперь внутри `appStartup`).
- `lib/ui/startup/widgets/startup_gate.dart` — `StartupGate({required Widget child, VoidCallback? onFirstFrame})`
  (`ConsumerStatefulWidget`; `onFirstFrame` по умолчанию — `WidgetsBinding.instance.allowFirstFrame`, в тестах — счётчик).
  По `ref.watch(appStartupProvider)`:
  - загрузка → `Scaffold` с `CircularProgressIndicator` по центру (при первом запуске его не видно — кадр отложен;
    виден только при повторной попытке);
  - данные → `child`;
  - ошибка → `StartupErrorScreen(onRetry: () => ref.invalidate(appStartupProvider))`.
  `onFirstFrame` вызывается **ровно один раз** — при первом переходе из загрузки в данные или ошибку (флаг в `State`).
  Не синхронно внутри `build`, а через `scheduleMicrotask` (*решение аналитика*): `addPostFrameCallback` не сработает,
  пока кадр отложен. Так сплеш не висит вечно: при ошибке или таймауте рисуется экран ошибки.
- `lib/ui/startup/widgets/startup_error_screen.dart` — `StartupErrorScreen({required VoidCallback onRetry})`,
  `Key('startup_error')`: по центру значок `Icons.error_outline` (56, цвет `error`), заголовок `startupErrorTitle`
  (`titleLarge`), текст `startupErrorMessage` (`bodyMedium`, `onSurfaceVariant`), `FilledButton` `startupRetry`.
  Подробности ошибки на экран не выводятся; ошибка пишется в `debugPrint` / `FlutterError.reportError`
  (*решение аналитика*).
- `lib/fusion_reflow_app.dart`: `MaterialApp.router(routerConfig: ref.watch(appRouterProvider), builder: (context, child)
  => StartupGate(child: child ?? const SizedBox.shrink()), …)`; тема, локализация и `themeMode` — как сейчас.
  `FusionReflowApp` становится `ConsumerWidget`.
- `lib/ui/home/widgets/home_screen.dart` удаляется.

### Android: сплеш

- `res/values/colors.xml` — `brand_background` `#0C0F22`.
- `res/drawable/launch_background.xml` и `res/drawable-v21/launch_background.xml` (Android 8–11): слой
  `@color/brand_background` + `bitmap` по центру `@drawable/ic_launcher_foreground` (генерирует
  `flutter_launcher_icons`).
- `res/values-v31/styles.xml` и `res/values-night-v31/styles.xml` (Android 12+): `LaunchTheme` с
  `android:windowSplashScreenBackground` = `@color/brand_background` и `android:windowSplashScreenAnimatedIcon` =
  `@drawable/ic_launcher_foreground`; `NormalTheme` как сейчас.
- `values/styles.xml`, `values-night/styles.xml`: `LaunchTheme` берёт `@drawable/launch_background` (уже так).
  Сплеш тёмный в обеих системных темах (как в макете).
- Без белой вспышки между сплешем и первым кадром: `NormalTheme` в `values` получает `android:windowBackground` =
  `@color/brand_background` *(решение аналитика)* — фон под Flutter до первого кадра тот же, что у сплеша.

### Android: иконка

`flutter_launcher_icons.yaml` в корне:
```yaml
flutter_launcher_icons:
  android: true
  ios: false
  image_path: assets/branding/logo_mark.png
  min_sdk_android: 26
  adaptive_icon_background: "#0C0F22"
  adaptive_icon_foreground: assets/branding/logo_mark.png
  adaptive_icon_foreground_inset: 16
  adaptive_icon_monochrome: assets/branding/logo_monochrome.png
```
- Генерация: `dart run flutter_launcher_icons`; сгенерированные `mipmap-*`, `drawable-*/ic_launcher_foreground.png`,
  `drawable-*/ic_launcher_monochrome.png`, `mipmap-anydpi-v26/ic_launcher.xml` коммитятся.
- Критерий размера знака — по доске «Иконки»: знак по центру с отступом около 20% от края видимой иконки. Если при
  `inset: 16` знак крупнее или мельче, разработчик подбирает `adaptive_icon_foreground_inset` и пишет итог в PR.
- `pubspec.yaml`, `flutter: assets:` — добавить `assets/branding/logo_mark.png` (нужен `AppLogo`).
  `logo_monochrome.png` в ассеты не входит.

## Критерии приёмки

- `dart format --set-exit-if-changed lib test integration_test test_driver tool && dart analyze --fatal-infos &&
  flutter test` — зелёные; `dart run build_runner build -d` не даёт изменений после коммита.
- Покрытие слоёв с логикой ≥ 85% (`tool/check_coverage.dart`), нового кода ≥ 85%.
- `dart run flutter_launcher_icons` не даёт изменений после коммита.
- `flutter build apk --flavor store --release` собирается; в release нет маршрута `/library/hyphen-spike`.
- Архитектурный тест проходит без правок.
- QA на Pixel 7 (`flutter clean`, debug и release `store`), скриншоты в PR:
  1. Холодный старт: тёмный сплеш `#0C0F22` с логотипом, без белой вспышки и без пустого кадра Flutter; затем
     Библиотека с нижней панелью из трёх пунктов (светлая и тёмная системная тема).
  2. Переходы по панели; повторный тап по активному пункту; «назад» с Закладок и Настроек ведёт в Библиотеку,
     с Библиотеки закрывает приложение.
  3. Иконка в лаунчере: адаптивная (круг), знак с полями около 20%; при включённых тематических иконках (Android 13+)
     — монохромная.
  4. Планшетная раскладка: `adb shell wm size 1640x2360` и `adb shell wm density 320` (ширина 820 dp) → рейка с
     логотипом сверху и «Настройками» внизу; поворот (1180 dp) → рейка; затем `adb shell wm size reset` и
     `adb shell wm density reset`.
  5. Debug: кнопка «Проверка переноса (debug)» на Библиотеке открывает спайк.

## Review Focus

- `allowFirstFrame` вызывается ровно один раз при любом исходе: успех, ошибка, таймаут, повтор после ошибки, повторная
  сборка `StartupGate` (смена темы или локали во время загрузки). Лишний вызов роняет движок, пропущенный — вечный сплеш.
- Повторная попытка после ошибки моста или базы: `RustLib.init` не вызывается дважды, база не открывается дважды
  (`appDatabaseProvider` — `keepAlive`).
- Медленная уборка сирот на большой библиотеке укладывается в `startupTimeout`; если нет — сказать человеку.
- Смена ширины окна на лету (поворот планшета, разделение экрана) переключает панель ↔ рейку без потери выбранного раздела.
- Ничего из `lib/src/rust/**` не импортируется вне `RustCoreService` (`init` — через сервис).
