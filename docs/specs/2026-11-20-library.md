# Библиотека: спека

**Задача плана:** 3.2 «Библиотека» (экран библиотеки по дизайну 2.2)
**Стек:** Flutter (+ Rust-пример для генерации debug-фикстур, если человек выберет вариант А в вопросе 1)
**Ветка:** `feat/library`
**Статус:** черновик. Ждёт ответов на открытые вопросы и подтверждения человека (шаг 2 пайплайна).

## Цель

Вкладка «Библиотека» показывает книги из хранилища (3.1) по макету: обложка-заглушка, название, автор, прогресс,
блок «Продолжить чтение», сортировка, пустое состояние. Тап по книге открывает заглушку читалки на сохранённой
позиции. В debug-сборке библиотеку можно наполнить тестовыми книгами до появления импорта (4.3).

## Открытые вопросы к человеку

Спека написана под рекомендованные ответы. Другой ответ меняет разделы, указанные в вопросе.

1. **Как получить книги-фикстуры в debug.** Мост умеет только читать CBOR (`book_meta`), кодировать книги из Dart
   нечем. `StubConverter` книгу не создаёт, он всегда возвращает `Unsupported`. `book_v1.cbor` один, а копии одной
   книги склеятся в одну запись: `add` проверяет хеш источника.
   - **А (рекомендую).** Пример `rust/flow-core/examples/debug_library_fixtures.rs` один раз собирает несколько
     синтетических книг и пишет их в `assets/debug_books/*.cbor`. Файлы коммитятся, приложение читает их через
     `rootBundle`. Минус: Flutter не умеет исключать ассеты из release, и в release-APK попадут несколько КБ
     неиспользуемых файлов. Код загрузки работает только при `kDebugMode`.
   - Б. Новое API моста, например `debug_sample_book(title, authors, seed) -> Vec<u8>`. Release-APK чистый, но
     API моста меняется. Это решение человека, и функция будет видна и в release-библиотеке.
   - В. Пакет `cbor` для Dart — новая зависимость, а формат блоков пришлось бы дублировать в Dart. Не рекомендую.
2. **Обложки.** В макете у каждой книги цветная обложка с автором и названием. Настоящей обложки нет нигде:
   `BookMeta` не отдаёт `Meta.cover`, в каталоге (`books`) нет поля под обложку, а импорта EPUB/FB2 (4.1, 4.2)
   ещё нет, поэтому книг с обложками тоже нет. Спека 3.1 отложила обложки «в 3.2 / 3.3».
   **Рекомендую:** в 3.2 только заглушка по макету (цвет по книге, автор и название на обложке). Настоящие обложки
   вынести в отдельную задачу вместе с 4.1/4.2. Для неё нужны новое API моста (извлечь картинку `Meta.cover`) и
   хранение (файл рядом с CBOR или поле в БД), а это вопрос человеку по AGENTS.md.
3. **Строка «Глава 1 · стр. 14 из 412» в «Продолжить чтение».** Страниц до читалки (5.2) нет. В
   `ReadingPosition` лежит только индекс главы, названия главы нет. **Рекомендую:** до 5.x показывать автора и
   процент («М. Булгаков · 34%»), а главу и страницы добавить задачей читалки.
4. **Поиск и меню «Ещё».** В макете телефона в шапке есть иконки «Поиск» и «Ещё» (⋮), на планшете — поле «Название
   или автор». В плане поиска по библиотеке нет, содержимое меню «Ещё» в макетах не нарисовано.
   **Рекомендую:** поиск в 3.2 не делать и иконку не показывать. Поиск добавить в план отдельной задачей, если он
   нужен в плане 2. Кнопка ⋮ в 3.2 есть только в debug и держит отладочные пункты (см. «Отладка»).
5. **Кнопка «Добавить» до 4.3.** План разрешает скрыть её или сделать заглушкой. В пустом состоянии макета написано
   «Нажмите «Добавить» внизу справа». **Рекомендую:** кнопку показывать, по тапу выводить `SnackBar` «Импорт
   появится в следующей версии». Релизов до 4.3 нет, поэтому пользователи заглушку не увидят.

Отмечу ещё одно расхождение. В спеке каркаса (`2026-11-17-app-shell.md`) записано решение человека: «маршрут экрана
чтения появится вместе с читалкой (5.3)». План 3.2 и бриф задачи просят заглушку читалки уже сейчас. Спека идёт
по плану: маршрут `/reader/:bookId` с экраном-заглушкой, который 5.3 заменит настоящим экраном.

## Границы

В задаче:
- экран «Библиотека» по макетам `library`, `library-small`, `library-tablet`, `library-wide`, `library-empty`
  (светлая и тёмная темы, телефон и планшет);
- блок «Продолжить чтение», сетка книг, обложка-заглушка, подпись прогресса и формата, счётчик книг;
- сортировка «Недавние / Название / Автор»;
- пустое состояние, состояния загрузки и ошибки;
- кнопка «Добавить» — заглушка (вопрос 5);
- маршрут и экран-заглушка читалки, открытие книги по тапу;
- debug: загрузка книг-фикстур и перенос кнопки спайка переносов в debug-меню;
- строки ru/en в ARB, юнит-, виджет- и golden-тесты.

Не в задаче (и где это делается):
- импорт, лист «Файл / Папка», состояние «импорт в процессе» на обложке (`library-importing*`) — 4.3;
- долгое нажатие, удаление, карточка книги — 3.3;
- настоящие обложки — отдельная задача (вопрос 2);
- поиск — вопрос 4;
- глава и страницы в «Продолжить чтение» — 5.x (вопрос 3);
- запоминание выбранной сортировки между запусками — 6.x, настройки приложения (*решение аналитика*: для него
  нужно хранилище настроек, а это новая зависимость или изменение схемы БД);
- настоящая читалка и сохранение позиции (`savePosition`) — 5.x. Библиотека позицию только читает.

## Интерфейсы

Существующее, что задача потребляет без изменений: `BookRepository.watchAll()` (3.1; живые книги, новые первыми),
`BookRepository.add`, `BookRepository.savePosition`, `BookEntry`, `ReadingPosition`, `BookFormat`,
`windowSizeClassOf` (`lib/utils/window_size_class.dart`), `AppDimens`, тема (`lib/ui/core/theme/`), `pumpApp`.
API моста, схема БД и `BookRepository` **не меняются** (при варианте А вопроса 1).

### Домен — `lib/domain/models/`

`library_sort.dart`:
```dart
/// Порядок книг в библиотеке.
enum LibrarySort { recent, title, author }

/// Книги в порядке [sort]; исходный список не меняется.
List<BookEntry> sortBooks(Iterable<BookEntry> books, LibrarySort sort);
```
Правила сравнения (*решение аналитика*):
- `recent`: по убыванию `lastReadAt ?? addedAt`;
- `title`: по возрастанию названия без учёта регистра, `ё` приравнивается к `е`. В `intl` нет сравнения строк по
  локали, а сравнение по кодам символов ставит «ё» после «я». Латиница идёт перед кириллицей (по кодам символов);
- `author`: по первому автору с теми же правилами; книги без автора идут в конце. Если первые авторы равны, книги
  сравниваются по названию;
- при равенстве ключей порядок задаёт `id`, чтобы сортировка была детерминированной.

`reading_status.dart`:
```dart
/// Состояние чтения книги для подписи в библиотеке.
enum ReadingStatus { fresh, reading, finished }

extension BookReadingStatus on BookEntry {
  /// fresh: lastReadAt == null && progress == 0; finished: progress >= 1; иначе reading.
  ReadingStatus get readingStatus;

  /// Процент для подписи: floor(progress * 100), в пределах 0..99 для reading
  /// (99,6% не показывается как 100%).
  int get progressPercent;
}
```

### ViewModel — `lib/ui/library/view_models/`

`library_state.dart` (freezed):
```dart
@freezed
abstract class LibraryState with _$LibraryState {
  const factory({
    required List<BookEntry> books,      // сетка: все книги, кроме continueReading, в порядке sort
    required int totalCount,             // все живые книги (для счётчика «8 книг»)
    required LibrarySort sort,
    BookEntry? continueReading,          // книга с наибольшим lastReadAt, если она не finished
  }) = _LibraryState;
}
```
Книга из «Продолжить чтение» в сетку не попадает, как в макете телефона: там в сетке нет «Мастера и Маргариты»
при сортировке «Недавние». Счётчик считает все книги. *Решение аналитика по макету.*

`library_view_model.dart`:
```dart
@riverpod
class LibraryViewModel extends _$LibraryViewModel {
  Stream<LibraryState> build();            // поверх bookRepository.watchAll(), сортировка по умолчанию recent
  void setSort(LibrarySort sort);          // пересобирает state без нового запроса к репозиторию
  Future<int> loadDebugFixtures();         // только debug; возвращает число добавленных книг
}
```
- Ошибка потока `watchAll` даёт `AsyncError` и экран ошибки с кнопкой «Повторить»
  (`ref.invalidate(libraryViewModelProvider)`). Сортировка при этом сбрасывается на `recent`, это допустимо.
- `loadDebugFixtures`: берёт фикстуры у `DebugFixtureRepository`, по каждой вызывает `bookRepository.add`, затем
  `savePosition(id, ReadingPosition.start, progress)` для фикстур с `progress > 0`. Книгу с `lastRead: true`
  сохраняет последней, чтобы она стала «Продолжить чтение». Повторный вызов книг не дублирует (`add` по хешу
  вернёт существующую), но позиции перезапишет — для debug это допустимо. Вне `kDebugMode` бросает `StateError`.

### Debug-фикстуры — `lib/data/repositories/debug_fixture_repository.dart`

```dart
/// Книга-фикстура для debug-сборки.
typedef DebugFixture = ({Uint8List bytes, BookFormat format, double progress, bool lastRead});

abstract interface class DebugFixtureRepository {
  Future<List<DebugFixture>> load();
}

/// Читает `assets/debug_books/*.cbor` из [AssetBundle] по фиксированному списку.
class AssetDebugFixtureRepository implements DebugFixtureRepository { new({required AssetBundle bundle}); }

@Riverpod(keepAlive: true)
DebugFixtureRepository debugFixtureRepository(Ref ref);   // AssetDebugFixtureRepository(bundle: rootBundle)
```
Список файлов, их форматы и `progress` — одна константа в этом файле. `AssetBundle` уже абстракция Flutter,
поэтому отдельный Service ради debug-кода не нужен (*решение аналитика*).

Набор фикстур (вариант А вопроса 1). Тексты синтетические, книги корпуса и реальные названия не используются

### Маршрут и заглушка читалки

- `AppRoutes.reader = '/reader/:bookId'` и `static String readerOf(String bookId)`. Маршрут верхнего уровня, вне
  `StatefulShellRoute`: читалка полноэкранная, без нижней панели и рейки. Открывается через
  `context.push(AppRoutes.readerOf(id))`, «Назад» возвращает в библиотеку с тем же скроллом.
- `lib/ui/reader/view_models/reader_placeholder_view_model.dart`: `@riverpod Stream<BookEntry?>
  readerPlaceholderViewModel(Ref ref, String bookId)` — книга из `watchAll()` по id или `null`.
- `lib/ui/reader/widgets/reader_placeholder_screen.dart` (`ReaderPlaceholderScreen`, ключ `reader_placeholder`):
  `AppBar` с «Назад», название книги, «Читалка появится позже», «Откроется на {percent}%» (позиция берётся из
  `BookEntry`). Если книги нет — «Книга не найдена». 5.3 заменит этот экран.

## Критерии приёмки

- `dart format --set-exit-if-changed lib test integration_test test_driver tool && dart analyze --fatal-infos &&
  flutter test` — зелёные; `dart run build_runner build -d` не даёт изменений после коммита.
- `flutter test --tags golden` проходит локально с закоммиченными эталонами.
- Из `rust/`: `cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test` — зелёные
  (вариант А: пример и тест фикстур). Повторный запуск генератора не меняет `assets/debug_books/` (`git diff`
  пустой).
- Покрытие `lib/domain`, `lib/data`, `lib/ui/**/view_models` ≥ 85%, нового кода ≥ 85%
  (`tool/check_coverage.dart`).
- Архитектурный тест проходит: `domain` не импортирует `ui`/`data`, ViewModel не обращается к сервисам.
- `flutter build apk --flavor store --release` собирается. В release нет кнопки ⋮ и маршрута спайка, код
  загрузки фикстур не вызывается.
- QA на Pixel 7, скриншоты в PR:
  1. чистая установка → пустое состояние по `library-empty` в светлой и тёмной теме;
  2. ⋮ → «Загрузить тестовые книги» → 6 книг, «Продолжить чтение» — «Тестовая книга о море · Иван Тестов · 34%»,
     подписи «Новая» / «72%» / «Прочитана», длинное название обрезано;
  3. сортировки «Название» и «Автор»: «Ёлка и ёжик» стоит между «A Test Book…» и «Книга без автора», книга без
     автора последняя в «Автор»;
  4. тап по книге → заглушка читалки с названием и процентом, «Назад» → библиотека на той же прокрутке;
  5. «Добавить» → SnackBar; поворот в альбомную ориентацию не теряет выбранную сортировку;
  6. повторная загрузка фикстур не создаёт дублей (по-прежнему 6 книг).

## Review Focus

- Огромная библиотека (сотни книг): сетка ленивая (`SliverGrid` / `GridView.builder`), сортировка не запускается
  на каждый кадр, только при новых данных или новой сортировке.
- Кривые данные из каталога: пустое название, пустые авторы, `progress` вне `0..1` (в БД он проверяется только
  при записи) — подпись не падает, процент зажат в пределы.
- Смена сортировки во время прихода нового списка из потока: порядок соответствует последнему `setSort`.
- Книга удалена, пока открыта заглушка читалки: экран переходит в «Книга не найдена» без исключения.
- Двойной тап по «Загрузить тестовые книги»: дублей нет (`add` по хешу), исключений нет.
- Размер шрифта системы 200%: карточки не переполняются (`overflow` в тестах не ловится).
- Release: нет ни ⋮, ни пути к фикстурам; строки из ARB без литералов в виджетах.

## Решения, принятые на гриллинге

Гриллинг с человеком ещё не проводился: аналитик работал в побочной сессии. Ниже решения аналитика, их можно
оспорить при валидации. Вопросы человеку собраны выше в «Открытых вопросах».

| Вопрос | Решение | Почему |
|---|---|---|
| Где сортировать | `sortBooks` в `lib/domain/models/library_sort.dart`, вызывается из ViewModel | `utils` не может импортировать `domain` (архитектурный тест), а репозиторию не нужен порядок отображения |
| Ключ «Недавние» | `lastReadAt ?? addedAt` по убыванию | только что добавленная книга оказывается наверху, прочитанная вчера — выше добавленной неделю назад |
| Сравнение названий | без учёта регистра, `ё` = `е`, затем `id` | в `intl` нет сравнения строк по локали; новая зависимость ради этого не нужна |
| Запоминать сортировку | нет, до задач настроек (6.x) | нужно хранилище настроек, а это новая зависимость или изменение схемы |
| «Продолжить чтение» | книга с наибольшим `lastReadAt`, кроме прочитанных; в сетке её нет | так в макете телефона |
| Подпись прогресса | «Новая» / «N%» / «Прочитана», `floor`, не больше 99 для читаемой | 99,6% не должно выглядеть как прочитанная книга |
| Колонки сетки | `max(2, ширина ~/ 150)` | даёт 2 / 4 / 6 колонок на ширинах макетов 390 / 820 / 1180 |
| Цвет заглушки обложки | палитра из макета, индекс по `sourceHash` | стабилен между запусками и устройствами, в отличие от `hashCode` |
| Сортировка на телефоне и планшете | compact — чип с меню, medium/expanded — три `ChoiceChip` | так в макетах `library` и `library-tablet` |
| Читалка | маршрут `/reader/:bookId` вне оболочки, экран-заглушка показывает позицию из `BookEntry` | читалка полноэкранная; 5.3 заменит экран, маршрут останется |
| Кнопка спайка переносов | в debug-меню ⋮ | на месте заглушки теперь экран библиотеки, а интеграционный тест спайка должен работать |
| Фикстуры: Service или нет | `AssetDebugFixtureRepository` над `AssetBundle` | `AssetBundle` уже абстракция Flutter, отдельный Service ради debug-кода — лишний слой |
| Golden | 4 эталона с тегом `golden`, CI пропускает | так устроен спайк переносов; спека темы обещала golden с экранами начиная с 3.2 |
